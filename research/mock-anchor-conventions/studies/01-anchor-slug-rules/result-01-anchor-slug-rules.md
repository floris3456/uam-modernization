# Result 01 — Anchor slug rules across renderers

**FACT.** GitHub, VS Code's markdown tooling, and most CommonMark-based editors derive heading anchors with the same core algorithm: lowercase the heading, remove punctuation and other non-word characters (except hyphens and underscores), replace runs of spaces with a single hyphen, and disambiguate duplicate slugs with a numeric suffix (`-1`, `-2`, …).

## Verified rules

1. **Lowercasing** — `## About this Gate` → `about-this-gate`.
2. **Punctuation removal** — `## 1.1 Plain-language recommendation` → `11-plain-language-recommendation` (periods, colons, commas removed).
3. **Space runs to hyphens** — multiple spaces collapse to one hyphen.
4. **Duplicate headings** — the second occurrence of the same heading gets `-1` appended; further duplicates increment.
5. **Non-ASCII letters** — GitHub keeps Unicode letters in slugs (e.g., `Über` → `über`). **UNVERIFIED:** whether the zaaack MDE extension matches GitHub for every non-ASCII case; the repository's validator uses ASCII-only slugging, so the safe rule is to keep headings ASCII.

## Consequence

The repository validator's `slugify` matches GitHub for ASCII headings, which is the practical case in this repository. Links generated by the validator therefore resolve in VS Code and on GitHub. When a heading must contain non-ASCII characters, the heading should be renamed to an ASCII equivalent instead of relying on renderer agreement.
