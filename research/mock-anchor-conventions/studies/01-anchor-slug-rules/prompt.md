## Accepted baseline and provisional matters

Accepted baseline: repository links use heading anchors; the validator implements `slugify` (lowercase, strip non-word characters, spaces to hyphens). Provisional: whether non-ASCII headings and duplicate headings follow GitHub slugging exactly, and whether VS Code and zaaack MDE agree.

## Research questions

1. What exact slug does GitHub produce for headings containing punctuation, non-ASCII letters, and duplicate text?
2. Do VS Code's built-in markdown links and the zaaack Markdown Editor resolve the same anchors?
3. What slug algorithm should the repository validator implement so links that pass validation also work in the user's editor?
