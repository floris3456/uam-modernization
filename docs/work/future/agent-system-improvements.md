# Agent-system improvement backlog

This file is non-normative. It records problems or experiments that may deserve future review. It does not change active instructions, skills, agents, configuration, branches, or authority boundaries.

## Entry format

- Observation and concrete evidence.
- Consequence.
- Smallest candidate improvement.
- Expected context/complexity cost.
- Required human decision or experiment.
- Link to the normative home if the change is accepted.

## Current themes

1. Prefer simple explanations and direct actions.
2. Do not silently substitute a similar tool or mechanism.
3. Instructions should support reasoning rather than dominate it.
4. Keep intentionally completed developer work synchronized with remote Git.
5. Recheck volatile connector/model capabilities when versions change.
6. Measure whether Project/local skill boundaries reduce context pollution in real tasks.

Do not duplicate accepted rules here. Once accepted, update the real normative home and leave only a concise link/evidence note in this backlog.
