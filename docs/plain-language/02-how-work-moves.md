# How work moves

1. The human states the goal.
2. The web orchestrator checks whether it is operating with or without MCP tools.
3. It inspects enough exact remote evidence to design one bounded task.
4. In MCP-ON mode it delegates to Luna by default; Sol is exceptional.
5. The developer works on `developer`, continuously maintains AS-BUILT and deviations, and pushes every commit.
6. Before returning, the developer pushes a task-progress snapshot and gives only a short navigational response.
7. The web orchestrator reviews the exact remote range independently and either steers, approves, or asks the human for a consequential decision.
8. After implementation approval, the implementing developer finalizes durable records and deletes task-progress.
9. The web orchestrator reviews finalization and asks the human about one exact `developer` SHA.
10. If approved, Luna mechanically merges that state into `main` and synchronizes `developer`.

The separate `web-orchestration` branch stores only focused web-orchestrator task context and never merges with implementation branches.
