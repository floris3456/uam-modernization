What are we proving?

Prove that reading Edge history never changes the source and never treats an incomplete copy as valid.

Why now?

Live acquisition is too risky until Windows isolation is proven.

What depends on it?

  • Profile, source-generation, and cursor proof in G3.

Preparation that may happen earlier

  • Build fictional SQLite histories and acquisition test cases from G0 fixtures.
  • Review Edge and SQLite documentation.

Work allowed

  • Fictional database tests and read-only acquisition prototypes after G0; live lab work only after G1.

Work prohibited

  • Write to a source profile.
  • Use real activity outside the approved isolated lab proof.
  • Send or log raw acquired values.

What must humans decide?

  • Approve the exact Edge/Windows tuples and live-lab safety procedure.

What must be measured with CLI evidence?

  • Before/after source hashes, filesystem and SQLite write monitoring, backup-integrity checks, lock/crash cases, bounded resource measurements, and cleanup.

What evidence is required?

  • Exact browser/database tuple, selected read path, negative results, source integrity proof, raw-containment scan, and cleanup receipt.

What causes failure or hold?

Stop on any source mutation, incomplete backup accepted, attributable corruption or crash, raw escape, progress after non-success, or residue.

Failure, reproduction, cleanup, and recovery

  • Stop reading, preserve only sanitized evidence, compare source state, clean copies, and do not retry until the cause is understood.

What does passing unlock?

  • Profile, source-generation, and cursor proof in G3.

What passing never authorizes

  • Production collection.

Pass condition

All supported read paths preserve source bytes and metadata as specified, incomplete backups defer, impact stays bounded, and raw values remain contained.
